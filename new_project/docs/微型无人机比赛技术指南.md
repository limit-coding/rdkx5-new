# 微型无人机比赛技术指南

> 根据 `微型无人机（线上）.pdf` 整理。本文面向组内协作，重点放在视觉 AI、YOLO 模型训练、本地验证和 RDK X5 板端部署。

## 1. 比赛任务摘要

场地为室内 `9m x 6m x 3m`，无人机需要全程自主完成以下任务：

1. 从起飞点起飞，比赛飞行高度通常不低于 `1.2m`。
2. 识别 `200mm x 200mm` 二维码，二维码内容为：

```text
类别1,类别2,left/right
```

示例：

```text
man,apple,left
```

3. 携带 3 个物块飞到障碍物处，顺时针绕 `600mm x 600mm x 600mm` 障碍物飞行。
4. 根据二维码中的两个 CIFAR-100 类别，把两个小物块投到对应图片靶。
5. 将第三个物块投到带红蓝闪烁信号灯的特殊靶。
6. 穿过位置不提前告知的圆环，圆环外径 `1.2m`，内径 `0.9m`，底部距地 `1m`。
7. 根据二维码中的 `left/right` 选择正确降落点，并尽量精准降落在 `H` 区域。

## 2. 规则带来的工程约束

硬件上，轴距必须在 `290mm ~ 360mm`，总重不大于 `2.5kg`，必须有桨叶保护装置。飞控不允许使用商业闭源飞控，建议使用开源飞控或自研飞控，并保留源码和参数说明。

软件上，比赛重点考察自主定位、路径规划、目标识别、自主避障和任务执行状态机。线上赛要求至少 3 个摄像头从不同角度拍摄场地，所以系统稳定性和可复现实验记录也很重要。

本项目已有基础：

- RDK X5 + ROS2/TROS。
- OpenCV 二维码识别节点：`camera/qr_show`。
- YOLO11 BPU 推理代码：`camera/camera/animal_detect_enable.py`。
- 激光雷达/里程计控制链路和 ROS2 主控框架。

## 3. 推荐系统架构

```text
摄像头/传感器
  -> 二维码识别
  -> 视觉 AI 检测/分类
  -> 定位与障碍感知
  -> 任务状态机
  -> 飞控控制指令
```

建议把任务状态机拆成以下阶段：

```text
待起飞
  -> 起飞到 1.2m
  -> 搜索/对准二维码
  -> 解析目标类别和降落方向
  -> 绕障计圈
  -> 搜索图片靶
  -> 投放类别1
  -> 投放类别2
  -> 搜索特殊靶并投放
  -> 搜索圆环并穿越
  -> 选择 left/right 降落点
  -> 精准降落与上锁
```

每个阶段都要有超时保护。例如二维码 10 秒未识别成功，则保持悬停并上报失败；投放前连续 3 到 5 帧目标一致再触发投放，避免单帧误检。

## 4. AI 方案总览

视觉任务可以分成 4 类，不建议全部交给一个模型硬做：

| 任务 | 推荐方案 | 是否需要训练 |
|------|----------|--------------|
| 二维码识别 | OpenCV `QRCodeDetector` | 不需要 |
| 图片靶位置与类别 | YOLO 检测或 YOLO 检测 + 分类 | 需要 |
| 特殊靶/信号灯识别 | YOLO 检测 + 颜色/闪烁规则判断 | 需要少量数据 |
| 圆环/降落点/障碍物 | YOLO 检测或传统视觉辅助 | 需要 |

### 4.1 模型选择结论

如果目标是尽快做出能跑通的比赛版本，推荐：

```text
第一版：YOLO11n 检测模型
```

原因：

- 本项目现有板端代码已经是 YOLO11 检测后处理，迁移成本最低。
- `n` 版本速度快，适合 RDK X5 这种机载边缘计算场景。
- 训练、导出、转换到 `.bin` 的流程比较成熟。

如果后续要升级，并且确认 RDK 工具链和板端后处理已经支持新模型，可以考虑：

```text
进阶版：YOLO26n / YOLO26n-cls
```

截至 2026-05-07，Ultralytics 官方文档已把 YOLO26 与 YOLO11 都列为推荐模型系列，D-Robotics/RDK 文档的 TROS 更新记录也提到目标检测算法支持 `yolo26`。但我们当前项目代码是 YOLO11 风格，所以建议先用 YOLO11n 稳住比赛主线。

### 4.2 两种训练路线

路线 A：单 YOLO 检测模型，适合比赛第一版。

```text
输入整张图
  -> YOLO11n 检测
  -> 输出类别和目标框
```

类别可以先定义为：

```text
qr
picture_target
special_target
ring
obstacle
landing_h
red_light
blue_light
```

图片靶中的 CIFAR-100 类别如果也想由 YOLO 一次识别，可以把类别扩展为 `100 个 CIFAR 类别 + special_target + ring + landing_h ...`。这种方式推理简单，但数据集制作压力较大。

路线 B：检测 + 分类，两阶段方案，适合正式冲分。

```text
YOLO11n 检测图片靶位置
  -> 裁剪图片靶中心图案
  -> YOLO11n-cls 或轻量分类模型识别 CIFAR-100 类别
```

这种方案更合理，因为 CIFAR-100 本质是分类数据集，不是目标检测数据集。检测模型负责“找靶”，分类模型负责“判断靶上图片是什么类别”。缺点是板端要多接一个分类推理流程。

推荐推进顺序：

1. 先做路线 A 的 `YOLO11n` 检测版，跑通整套状态机。
2. 如果图片类别识别不稳定，再升级到路线 B。

## 5. 数据集制作

### 5.1 需要采集哪些数据

至少准备这些图片：

| 数据 | 采集方式 | 建议数量 |
|------|----------|----------|
| 二维码 | 直接测试即可 | 不训练 |
| 图片靶 | 打印赛方图片靶，室内多角度拍摄 | 每类 30 到 100 张 |
| 特殊靶 | 红蓝灯不同闪烁状态 | 300 张以上 |
| 圆环 | 不同距离、偏航、光照 | 300 张以上 |
| 降落点 H | 左/右两个降落点，不同高度 | 200 张以上 |
| 障碍物 | 绕障过程视角 | 200 张以上 |

训练数据一定要模拟比赛视角：无人机摄像头高度、运动模糊、室内光照、倾斜角度和目标被部分遮挡都要覆盖。

### 5.2 CIFAR-100 图片靶数据

比赛图片来自 CIFAR-100。不要只用原始 `32x32` 小图训练，因为比赛看到的是“打印后的图片靶”，相机拍到的是纸面、透视、光照和模糊后的图像。

建议制作两类数据：

1. 合成数据：把 CIFAR-100 图片放到图片靶模板中，随机旋转、透视变换、加模糊、加噪声、调亮度。
2. 实拍数据：打印一批类别，放在真实场地里用无人机摄像头拍，作为验证集和少量微调数据。

合成数据用于扩大覆盖面，实拍数据用于贴近比赛现场。

### 5.3 YOLO 检测数据目录

```text
datasets/micro_drone_det/
  images/
    train/
    val/
  labels/
    train/
    val/
  micro_drone_det.yaml
```

`micro_drone_det.yaml` 示例：

```yaml
path: datasets/micro_drone_det
train: images/train
val: images/val
names:
  0: picture_target
  1: special_target
  2: ring
  3: obstacle
  4: landing_h
  5: red_light
  6: blue_light
```

标签格式为 YOLO 标准格式：

```text
class_id x_center y_center width height
```

坐标全部是 0 到 1 的归一化值。

### 5.4 分类数据目录

如果使用分类模型，目录按类别分文件夹：

```text
datasets/cifar100_target_cls/
  train/
    apple/
    man/
    ...
  val/
    apple/
    man/
    ...
```

图片内容建议是从图片靶中心裁剪出来的图案区域，而不是整张场地照片。

## 7. YOLO11n 检测模型训练

第一版建议从 `yolo11n.pt` 开始：

```bash
yolo detect train \
  model=yolo11n.pt \
  data=datasets/micro_drone_det/micro_drone_det.yaml \
  imgsz=640 \
  epochs=120 \
  batch=16 \
  device=0 \
  project=runs/micro_drone \
  name=yolo11n_det
```

训练完成后，常用文件在：

```text
runs/micro_drone/yolo11n_det/weights/best.pt
```

验证：

```bash
yolo detect val \
  model=runs/micro_drone/yolo11n_det/weights/best.pt \
  data=datasets/micro_drone_det/micro_drone_det.yaml \
  imgsz=640 \
  device=0
```

本地摄像头或视频测试：

```bash
yolo detect predict \
  model=runs/micro_drone/yolo11n_det/weights/best.pt \
  source=0 \
  imgsz=640 \
  conf=0.3
```

验收目标：

- `picture_target`、`ring`、`landing_h` 不能频繁漏检。
- 特殊靶信号灯如果框不稳定，可以只让 YOLO 找特殊靶，再用颜色阈值判断红蓝灯。
- 误检比漏检更危险，比赛状态机里要做连续多帧确认。


## 9. 导出与 RDK X5 部署

RDK X5 的 BPU 适合跑量化后的模型。不要直接在 CPU 上跑 PyTorch YOLO，帧率会很低。

推荐流程：

```text
best.pt
  -> ONNX
  -> RDK 工具链量化/转换
  -> .bin
  -> 放入 camera/resource/
  -> 修改板端模型路径和类别数
```

导出 ONNX：

```bash
yolo export \
  model=runs/micro_drone/yolo11n_det/weights/best.pt \
  format=onnx \
  imgsz=640 \
  opset=12 \
  simplify=True
```

量化校准数据建议使用比赛现场照片，数量至少 100 到 300 张。校准数据不要只用网络图片，否则板端精度可能明显下降。

板端替换检测模型时，需要改：

```python
# camera/camera/animal_detect_enable.py
model_path = "/home/sunrise/ros2/diansai/ws/src/camera/resource/your_model.bin"
conf_thres = 0.3
iou_thres = 0.5
model = YOLO11_Detect(model_path, conf_thres, iou_thres, 类别数)
coco_names = ["picture_target", "special_target", "ring", ...]
```

如果类别数从 5 类改成 7 类、100 类或更多，必须同步修改 `classes_num` 和类别名列表。

二维码不建议训练模型，直接使用当前 OpenCV 方案：

```bash
source /opt/ros/humble/setup.bash

```

输出话题：

```text

```

```text

```

## 11. 飞行任务实现步骤

### 第一步：静态识别跑通

1. USB 摄像头正常发布 `/image`。
2. `qr_show` 能稳定输出二维码文本。
3. YOLO 检测模型能在本地视频里识别图片靶、特殊靶、圆环、降落点。
4. 板端 `.bin` 模型推理能达到可用帧率。

### 第二步：悬停识别跑通

1. 无人机起飞到 `1.2m` 并悬停。
2. 开启二维码识别，解析两个类别和降落方向。
3. 开启 YOLO 推理，连续多帧确认目标。
4. 发布目标中心偏差 `dx, dy` 给控制模块。

### 第三步：视觉伺服对准

基于目标框中心：

```text
dx = target_center_x - image_center_x
dy = target_center_y - image_center_y
```

简单控制逻辑：

```text
|dx| 大 -> 左右微调
|dy| 大 -> 前后微调
目标框面积小 -> 靠近
目标框面积大 -> 后退或保持
```

实际飞行时要限速，避免图像抖动导致来回震荡。

### 第四步：投放逻辑

投放前必须满足：

```text
目标类别正确
目标框中心接近画面中心
高度满足投放要求
连续 N 帧识别一致
```

比赛规则里悬停投放高度不得高于 `0.8m`，而正常飞行高度不得低于 `1.2m`。因此投放阶段要从巡航高度下降到投放高度，投放完成后再回到安全巡航高度。

### 第五步：圆环穿越

检测到圆环后，先用视觉对准圆心，再保持高度穿越。圆环底部距地 `1m`，内径 `0.9m`，无人机需要留足姿态和护桨余量。建议穿越前降低速度，穿越后再恢复巡航。

### 第六步：降落

二维码给出的 `left/right` 决定降落点。视觉检测到 `landing_h` 后，先对准中心，再分阶段下降：

```text
1.2m -> 0.8m：正常下降
0.8m -> 0.3m：慢速修正中心
0.3m -> 触地：低速下降，接地后上锁
```

## 14. 调参建议

视觉阈值：

```text
conf_thres = 0.25 ~ 0.45
iou_thres = 0.45 ~ 0.60
连续确认帧数 = 3 ~ 5
```

飞行控制：

```text
巡航高度 = 1.2m
投放高度 <= 0.8m
视觉对准速度 = 低速
穿环速度 = 低速
降落末段速度 = 更低速
```

训练指标不要只看 mAP。比赛真正关心的是：

- 现场光照下能不能识别。
- 运动模糊时能不能稳定。
- 类别是否会混淆。
- 误检会不会触发错误投放。
- 板端帧率是否足够支撑控制。
