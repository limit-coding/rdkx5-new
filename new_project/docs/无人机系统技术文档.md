## 一、系统概述

本系统是一套运行在 **地瓜派 RDK X5 机载电脑**上的 **ROS2 无人机自主定点飞行系统**，专为室内微型无人机比赛设计。系统以 **Livox MID-360 激光雷达** 作为主定位传感器，通过 **FAST-LIO** 算法实时构建环境地图并获取精确里程计，再经 C++ 定位链路将位置误差实时发送至 **匿名凌霄飞控**，实现高精度室内定点飞行。

### 核心指标

| 指标 | 数值 |
|------|------|
| 定点精度（XY） | ≤ ±0.1 m |
| 定位更新频率 | 20 Hz |
| 起飞/巡航高度 | 1.2 m |
| 串口通信波特率 | 115200 bps |
| 雷达扫描点数 | ~19968 点/帧 |

## 四、C++ 定位链路详解

### 4.1 MID-360 数据预处理节点 (`mid360_xy_cpp`)

**功能**：订阅 Livox 驱动发布的 `/livox/lidar`（`CustomMsg` 格式），将点云转换为标准 `sensor_msgs/PointCloud2`，供 FAST-LIO 消费，同时每秒打印一次当前帧点数与平均距离用于健康监测。

```
/livox/lidar (CustomMsg)
    │
    ▼  customToPointCloud2()
/mid360/xy_points (PointCloud2, XYZ float32)
    │
    ▼
FAST-LIO → /Odometry
```

**关键参数**：
- 发布频率：与雷达扫描频率同步（约 10 Hz）
- 点云格式：XYZ float32，point_step = 12 字节

### 4.2 相对位姿计算节点 (`relative_pose_cpp`)

这是定位链路的核心节点，完成从全局里程计到机体坐标系相对位移的换算。

#### 坐标系定义

```
开机原点坐标系（relative_origin）：
  - 原点：第一帧有效 Odometry 接收时的位置
  - +X 轴：开机时机头朝向（use_initial_heading_frame = true 时）
  - 高度：直接取 Odometry 的 z 坐标差

FAST-LIO map 坐标系：
  - 全局 ENU 坐标，随建图累积
  - 原点可能随 SLAM 漂移
```

#### 相对位移计算流程

```
收到 /Odometry (pos.x, pos.y, yaw)
        │
        ▼
① 首帧有效时记录原点：
   origin_x = pos.x, origin_y = pos.y
   origin_yaw = current_yaw + yaw_offset
        │
        ▼
② 计算 map 坐标系相对位移：
   map_rel_x = pos.x - origin_x
   map_rel_y = pos.y - origin_y
        │
        ▼
③ 旋转到机头坐标系（use_initial_heading_frame = true）：
   rel_x = map_rel_x * cos(origin_yaw) + map_rel_y * sin(origin_yaw)
   rel_y = -map_rel_x * sin(origin_yaw) + map_rel_y * cos(origin_yaw)
        │
        ▼
④ 发布 /relative_pose 和 /position_error
   /localization_valid = (稳定时间 ≥ 2s) AND (相对距离 ≤ 5m)
```

#### 可配置参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `target_x` / `target_y` | 0.0 | 目标点坐标（米） |
| `max_position_jump` | 5.0 m | 单帧 Odometry 跳变阈值 |
| `max_consecutive_errors` | 5 次 | 连续异常触发重置的次数 |
| `max_relative_meters` | 5.0 m | 相对位移安全范围上限 |
| `valid_after_sec` | 2.0 s | 原点设定后等待稳定的时间 |
| `odom_timeout_sec` | 1.0 s | Odometry 超时判定时间 |
| `use_initial_heading_frame` | true | 是否以开机机头方向为 +X |
| `yaw_offset_deg` | 0.0° | 机头方向偏置补偿 |
| `swap_xy` / `invert_x` / `invert_y` | false | 坐标轴调整选项 |

### 4.3 飞控桥接节点 (`fc_bridge_cpp`)

**功能**：以固定 20 Hz 频率将相对位置误差编码为 ANO LX 定点协议帧，通过串口发送至飞控。当定位状态无效或坐标异常时，自动降级为全零心跳帧，保证飞控不因异常坐标而失控。

#### 发送逻辑决策树

```
定时器触发 (20 Hz)
        │
        ├── fd_ < 0 ──► 启动重连定时器 (2s) ──► return
        │
        ├── 未收到 /relative_pose ──► 发送零帧（心跳）
        │
        ├── /localization_valid = false
        │   或距上次有效超过 0.5s ──────────► 发送零帧（心跳）
        │
        ├── 坐标包含 NaN/Inf ──────────────► 发送零帧（心跳）
        │
        ├── |x| > 2.0m 或 |y| > 2.0m ────► 发送零帧（心跳）
        │
        └── 正常 ──► 编码实际坐标 ──► 发送位置帧
```

#### 串口自动重连

串口断开后，节点不会崩溃，而是每 2 秒尝试重新打开 `/dev/ttyFC`，重连成功后自动恢复正常发送，提升系统鲁棒性。

## 五、飞控通信协议 (ANO LX)

### 5.1 定点位置帧格式

飞控桥接节点发送的定点协议帧格式如下：

```
字节偏移   字段          长度      说明
─────────────────────────────────────────────────────────────
  0        帧头 1        1B        固定 0xAA
  1        帧头 2        1B        固定 0xFF
  2        功能码        1B        0x01（定点位置帧）
  3        数据长度      1B        0x06（6字节有效载荷）
  4~5      X 坐标        int16 BE  相对原点 X 位移，单位：厘米
  6~7      Y 坐标        int16 BE  相对原点 Y 位移，单位：厘米
  8~9      YAW 角度      int16 BE  偏航角，单位：度
  10       校验和        1B        前10字节累加和 & 0xFF
─────────────────────────────────────────────────────────────
帧总长：11 字节
字节序：大端（高位在前）
```

**示例帧**（X=38cm, Y=2cm, YAW=7°）：
```
AA FF 01 06 00 26 00 02 00 07 DF
```

### 5.2 校验和计算

```cpp
uint8_t checksum = 0;
for (size_t i = 0; i < 10; i++) {
    checksum += frame[i];
}
frame[10] = checksum;
```

### 5.3 飞控侧解析（`ctrl.c` `My_CMD` case 4）

飞控接收到功能码 `0x01` 的帧后，提取 X/Y/YAW 误差，调用 `toradarpoint()` 函数计算速度指令并下发给电机控制层：

```c
// 飞控侧关键调用（ctrl.c）
case 4:
    toradarpoint(
        data_from_nuc.real_data.dx,    // X 误差 (m)
        data_from_nuc.real_data.dy,    // Y 误差 (m)
        data_from_nuc.real_data.dz,    // Z 误差 (m)
        data_from_nuc.real_data.dyaw,  // YAW 误差 (deg)
        0.03, 0.03, 5                  // 死区参数
    );
    break;
```

| 波特率 | 115200 bps |
| 数据位 | 8 |
| 停止位 | 1 |
| 奇偶校验 | 无 |
| 发送频率 | 20 Hz |

## 六、飞控 PID 定点控制

### 6.1 核心控制函数 `toradarpoint()`

飞控内部（`ctrl.c`）的定点控制函数接收上位机发来的位置误差，计算水平速度指令：

```
接收 (error_x, error_y, error_z, error_yaw)
          │
          ▼
    误差 > 0.2m → 快速 PID (Kp=125, Ki=5)
    误差 ≤ 0.2m → 慢速 PID (Kp=125, Ki=5)
          │
          ▼
    输出速度指令 sp_x / sp_y / sp_z / sp_yaw
          │
          ▼
    死区过滤（0.03m / 5°）
          │
          ▼
    写入 rt_tar 目标速度结构体 → 电机控制
```

### 6.2 控制环路结构

```
上位机（RDK X5）               飞控（ANO LX）
─────────────────           ──────────────────────
FAST-LIO 里程计              位置环 PID
    │                           │
relative_pose_cpp               速度环 PID
    │ 位置误差(X,Y,YAW)          │
fc_bridge_cpp ───串口帧──►  toradarpoint()
                                │
                            姿态环 PID
                                │
                            电机 PWM 输出
```

## 七、安全保护机制

### 7.1 定位有效性守卫（`relative_pose_cpp`）

系统设计了多层定位保护，避免 FAST-LIO 异常数据直接传至飞控导致飞机失控：

| 保护条件 | 触发动作 |
|----------|---------|
| 首帧 Odometry 绝对值 > 50 m | 拒绝设定原点，等待有效数据 |
| 单帧位置跳变 > 5 m | 丢弃当前帧，累计异常计数 |
| 连续 5 帧异常 | 重置原点，将 `/localization_valid` 置 false |
| 相对位移 > 5 m | 跳过本帧发布，置 `/localization_valid` false |
| Odometry 超时 > 1 s | 置 `/localization_valid` false，告警 |
| 原点设定后 < 2 s | SLAM 初始化稳定期，不发送真实坐标 |

### 7.2 飞控桥接守卫（`fc_bridge_cpp`）

| 保护条件 | 触发动作 |
|----------|---------|
| `/localization_valid` = false | 发送全零心跳帧（飞机悬停） |
| 有效状态超时 > 0.5 s | 发送全零心跳帧 |
| 坐标含 NaN / Inf | 发送全零心跳帧，告警 |
| `|x|` 或 `|y|` > 2 m | 发送全零心跳帧，告警 |
| 串口断开 | 启动 2 s 重连定时器，自动恢复 |

### 7.3 异常恢复流程

```
定位异常发生
      │
      ▼
fc_bridge_cpp 检测到 valid = false
      │
      ▼
发送零帧 → 飞控进入悬停保持
      │
      ▼
relative_pose_cpp 重置原点
      │
      ▼
FAST-LIO 恢复后发布新 Odometry
      │
      ▼
relative_pose_cpp 重新设定原点
      │
      ▼
等待 2 秒稳定期后 valid = true
      │
      ▼
fc_bridge_cpp 恢复发送实际坐标
```

### 8.3 雷达定位偶发异常分析

**现象描述**：

在测试过程中，雷达里程计（FAST-LIO `/Odometry`）会不定期出现数据突变，表现为坐标瞬间跳变至数百米甚至归零，随后自动恢复。如图 2/3 所示，典型日志如下：

```
[relative_pose_cpp] Odometry 跳变过大: 5.061m (阈值 5.000m), 连续异常 2/5
[relative_pose_cpp] 相对位移: dx=-672.024m, dy=+296.689m → 判定为定位失效
[relative_pose_cpp] 连续异常次数过多，判定为定位失效，重置原点等待恢复...
[fc_bridge_cpp] 坐标超出安全范围，发送 0cm 心跳帧
[relative_pose_cpp] Odometry 恢复正常
```

**原因分析**：

FAST-LIO 在快速运动或环境特征稀疏区域时，点云匹配可能短暂发散，导致里程计输出非物理跳变。系统的多层防护机制（跳变检测 + 连续异常计数 + 安全范围限制）能够有效拦截这类异常，使飞控在异常期间保持悬停而非飞走。

**已有保护效果**：
- 异常持续时间通常 < 1 秒，恢复后系统自动继续正常工作
- 飞控在异常期间持续收到零帧，保持当前悬停姿态
- 在完整飞行测试中，即使出现此类异常，无人机均能稳定保持位置

```bash
# 启动完整定位链路（雷达驱动 + FAST-LIO + C++ 定位节点）
ros2 launch lidar_fc_cpp auto_flight_cpp.launch.py
```

### 9.4 运行频率验证

```bash

ros2 topic hz /Odometry          # 预期：~10 Hz

```

### 9.5 关键参数调整

**修改飞控串口设备**（如串口路径不同）：

```python
parameters=[{
    'serial_port': '/dev/ttyFC',  # 修改为实际设备路径

```

**修改最大安全位移**（防止大范围移动触发保护）：
